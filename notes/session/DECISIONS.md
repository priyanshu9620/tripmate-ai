# Decisions (append-only)

- **D-1 · 2026-11-11 · Scope = both TripMate resume lines; everything is built.** The lines were borrowed as a writeup from another resume; there is no repo and no hand-written code to protect. The Bedrock RAG project is out of scope for now.
- **D-2 · 2026-11-11 · Stack = Python 3.11 (uv) · LangGraph 1.x · LangChain `init_chat_model` · FastAPI · Postgres 16 · Docker Compose · GitHub Actions · Terraform (AWS).** Same toolchain as Pager-Zero so the method, Makefile shape, and lessons (P-2 Homebrew interpreter, pinned deps) carry over. All dependencies pinned exactly.
- **D-3 · 2026-11-11 · Provider-agnostic LLM via `init_chat_model`; default = `google_genai` / `gemini-3.5-flash-lite` (free, proven in Pager-Zero).** `.env.example` lists anthropic / google_genai / groq / ollama blocks like Pager-Zero. Every number in the report states which model produced it.
- **D-4 · 2026-11-11 · Four specialized agents + a supervisor, each a LangGraph node with its own tool set.** (1) `researcher` — geocode destination, weather window, points of interest; (2) `planner` — builds a day-by-day itinerary from research + constraints; (3) `budgeter` — searches flights/hotels, totals cost against the budget, proposes swaps; (4) `booker` — the only agent that calls mutating tools (`book_flight`, `book_hotel`). The supervisor routes by state (missing constraints → ask user; research done → plan; plan done → budget; user approved → book). Explicit graph edges, not a free-form "agents chat" loop, so routing is testable without an LLM.
- **D-5 · 2026-11-11 · Tools: free live APIs where they exist, deterministic local providers where they don't.** Live (no key): Open-Meteo (weather), Nominatim/OpenStreetMap (geocoding), Overpass (POIs). Flights and hotels have no free real API → an in-repo `providers/` package with seeded, deterministic inventory and prices (CSV fixtures). `TOOLS_MODE=offline` (default for tests + bench) uses recorded fixtures for the live ones too, so the eval is reproducible and runs with no network. The README says plainly that bookings are simulated.
- **D-6 · 2026-11-11 · Human-in-the-loop = LangGraph `interrupt()` before the `booker` node.** The graph pauses with the proposed bookings + total; the client (CLI or API) resumes with `approve` / `reject` / edited constraints. The interrupt survives a server restart because state is checkpointed (D-7) — that round-trip is one of the measured proofs.
- **D-7 · 2026-11-11 · Persistent conversation memory = LangGraph `PostgresSaver` checkpointer (per-thread) + `PostgresStore` (cross-thread user preferences such as "window seat", "vegetarian", home airport).** No ad-hoc tables for conversation state. A `trips` table (SQLAlchemy) holds the final itinerary and booking refs so the API can list past trips without replaying the graph. Alembic for migrations.
- **D-8 · 2026-11-11 · Serving = FastAPI (`/threads`, `/threads/{id}/messages`, `/threads/{id}/approve`, `/trips`, `/healthz`, `/metrics`) + Typer CLI (`tm chat`, `tm approve`, `tm trips`) + a tiny static `/ui` chat page (Pager-Zero style, no build step).** Streaming responses via SSE on the messages endpoint. `/metrics` via `prometheus_client` so the bench can scrape request latency and tool-call counts.
- **D-9 · 2026-11-11 · Numbers are measured by `bench/`, never asserted. Two benchmarks, reported separately.** (a) **Agent bench** (`make bench`): 20 fixed trip scenarios in `bench/scenarios.yml` (destination, dates, budget, travellers, constraints) run end-to-end through approve; records per run: wall latency, LLM calls, tokens in/out, estimated cost, tool calls, and a *deterministic* quality check (right number of days, budget respected, every day has ≥1 activity, dates inside the window, no POI outside the destination) → `results.json`. (b) **API/load bench** (`make load`): k6 in a container against the compose stack with `LLM_PROVIDER=fake` (scripted deterministic responses), ramping VUs until p95 > 500 ms or errors > 1 % — this measures FastAPI + checkpointer + Postgres overhead honestly, and the report states that the LLM is stubbed. Plus (c) **durability proof**: script starts a conversation, kills the API container mid-interrupt, restarts, resumes — pass/fail over 10 repetitions. Report (`bench/report.md` + SVG charts + `results.json`) is generated by `bench/report.py` and always carries a "what this does NOT prove" section.
- **D-10 · 2026-11-11 · LangSmith tracing is optional and env-driven (`LANGSMITH_TRACING=true` + key).** The agent bench uploads one tagged run set when the key is present; a screenshot of a traced multi-agent run goes in the report. Without the key everything still runs. Also keep a local fallback: LangGraph's run log is written as JSONL per thread so "debugged agent runs" is demonstrable offline too.
- **D-11 · 2026-11-11 · CI/CD = GitHub Actions, two workflows.** `ci.yml` on PR: ruff, pytest (offline tools, fake LLM), docker build. `deploy.yml` on push to `main`: build + push image to GHCR tagged with the SHA, then deploy to AWS (D-12) via SSM Run Command, then smoke `GET /healthz` through the public URL. AWS auth via OIDC role, no long-lived keys in GitHub.
- **D-12 · 2026-11-11 · AWS = one `t3.micro`/`t4g.micro` EC2 in `ap-southeast-2` running the app + Postgres via docker compose, behind an ALB, all from Terraform in `infra/`.** Reuses the ShopEase free-plan project (profile `shopease`, SCP allows EC2/ELB/S3/CloudFront, App Runner denied; shopease-notes D-21). Postgres on the same box is acceptable because the stack lives only for the deploy-test-screenshot window; RDS is not in the allow list and would add cost. The stack is up for the shortest possible window and destroyed by the user with `terraform destroy`. Claude never runs apply/destroy.
- **D-13 · 2026-11-11 · Demo in 2 minutes = `make demo`.** Brings up compose, opens `/ui`, runs a scripted conversation (Goa, 4 days, ₹40k, 2 people) up to the approval interrupt, shows the pause, approves from the CLI, shows the booked trip in `tm trips`, then restarts the API and shows the thread resuming. `DEMO.md` has the script and what to say.
- **D-14 · 2026-11-11 · Tests: pytest, offline, no LLM.** Graph routing tests drive the supervisor with a fake model; each tool has unit tests on fixtures; one integration test runs the full graph with the fake LLM against a Postgres test container. CI must be green with zero network.
- **D-15 · 2026-11-11 · Docs like Pager-Zero.** README (pitch, architecture diagram, measured-numbers table, how to run, roadmap), `docs/GUIDE.md`, `INTERVIEW_PREP/` (6 files), `DEMO.md`. Nothing from any employer anywhere.
